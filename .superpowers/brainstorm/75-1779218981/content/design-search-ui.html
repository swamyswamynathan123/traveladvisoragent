Design — Section 3: Parallel Search + Expedia + UI

Faster searches, real hotel data, and clickable follow-ups

3a — Parallel Search (ThreadPoolExecutor)

Before (sequential ~8–10s)
search("Paris top attractions") → wait
search("Paris travel tips") → wait
search("Paris food dining") → wait
search("best hotels Paris") → wait
search("best hotels Lyon") → wait
Total: 5 × ~1.5s = ~8s before LLM even starts
After (parallel ~2–3s)
┌ search("Paris top attractions")
├ search("Paris travel tips")
├ search("Paris food dining")
├ search("best hotels Paris")
└ search("best hotels Lyon")
All 5 fire at once → done in ~2s

Implementation: replace the for query, search_fn in search_tasks loop in search_with_tavily_node with ThreadPoolExecutor.map(). No architectural changes needed.

3b — Expedia MCP for Real Hotel Data

Current: Tavily scrapes TripAdvisor hotel pages → inconsistent, often just review summaries

New: dedicated expedia_hotel_search() wrapper added to tools.py
 → calls mcp__claude_ai_Expedia__search_hotels(destination, check_in, check_out, adults)
 → returns real listings: name, star rating, price/night, neighborhood, amenities
 → runs in parallel alongside Tavily searches (same ThreadPoolExecutor pool)
 → results injected into hotel_context section of the itinerary prompt

⚠ Requires: destination has a check-in date set. Falls back to Tavily if no date provided.
