Design — Section 2: Prompt Strategy

What changes in each prompt and why it fixes generic/shallow/impersonal responses

Problem: Current ITINERARY_GENERATION_PROMPT

"Create a detailed day-by-day travel itinerary based on the information below.
Trip Request: {trip_request}
Traveler Profile: {user_profile}
..."

❌ No explicit personalization enforcement — model often ignores interests/budget/pace
❌ Activities are named but no depth: "Visit the Louvre" with 1-sentence notes
❌ No practical logistics per activity (how to get there, best arrival time, book in advance?)
❌ Budget only used for hotels — not woven into activity choices or dining

Fix: New ITINERARY_GENERATION_PROMPT structure

STEP 1 — Personalization contract (new)
"Before writing anything, confirm you will honor ALL of the following:
 • Budget: {budget_level} — every hotel, restaurant, and activity must match this tier
 • Pace: {pace} — {pace_description}
 • Interests: {interests} — at least 60% of activities must directly reflect these
 • Constraints: {constraints} — these are hard rules, never violate them"

STEP 2 — Activity depth rules (strengthened)
"For EVERY activity block:
 • Use the specific venue name (e.g. 'Mercado de San Miguel', not 'a local market')
 • Write 2–3 sentences: what it is, why it matches THIS traveler, one practical tip
 • Include: how to get there, how long to spend, best time to arrive, book-ahead flag"

STEP 3 — Budget weaving (new)
"budget-tier guidance injected per level:
 budget → free attractions, street food, hostels, public transit
 mid_range → paid attractions, sit-down restaurants $$, 3-star hotels
 luxury → skip queues, tasting menus, 4–5 star, private transfers"

STEP 4 — Logistics block (strengthened)
"logistics_notes must cover: exact transport between each day's areas,
which activities need advance booking and how far ahead,
rough daily spend estimate at the stated budget level"

New: PERSONALIZATION_CHECK_PROMPT (Claude Haiku, ~1s)

"You are a quality reviewer for a travel itinerary.

The traveler requested:
 • Interests: {interests}
 • Budget: {budget_level}
 • Pace: {pace} ({pace_description})
 • Constraints: {constraints}

Review the itinerary below. For each day, check:
1. Do activities reflect the stated interests? (flag mismatches)
2. Are hotel/restaurant tiers consistent with budget_level?
3. Does the number of activities per day match the stated pace?
4. Are all constraints honored?

Return the same itinerary JSON with violations fixed.
Only change fields that violate the above — do not rewrite the whole plan."

Fix: collect_requirements & ask_clarification nodes

Before: json.loads(response.content) ← breaks silently if LLM adds a preamble

After: llm.with_structured_output(IntentDetectionOutput) ← Pydantic model enforced
       New schema: IntentDetectionOutput(intent, trip_request, travel_question, clarification_needed)
