Design — Section 1: Architecture

What changes in the graph and which new components are added

Current Graph

collect_requirements → validate_inputs → ask_clarification (if needed)
                            ↓
               search_with_tavily (sequential, 5–6 serial HTTP calls)
                            ↓
               generate_response (GPT-4o, raw JSON parsing)
                            ↓
               respond_to_user

New Graph (Approach C)

collect_requirements (structured output, no raw JSON)
→ validate_inputs
→ ask_clarification (if needed, structured output)
                            ↓
               search_with_tavily (parallel: ThreadPoolExecutor)
               + expedia_hotel_search (runs alongside Tavily)
                            ↓
               generate_response (Claude Sonnet 4.6, rewritten prompts)
                            ↓ (itinerary only)
               ✨ NEW: personalization_check (fast Claude Haiku pass)
                            ↓
               respond_to_user

5 Key Changes

Component Before After
LLM (generation) GPT-4o Claude Sonnet 4.6
Search Sequential (5–6 calls, ~8s) Parallel (same calls, ~2–3s)
Hotel data Tavily scrape (unreliable) Expedia MCP (real listings)
JSON parsing json.loads() — silent failures with_structured_output everywhere
Personalization No post-generation check Haiku verifies & patches itinerary
